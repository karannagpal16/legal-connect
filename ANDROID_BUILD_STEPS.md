# Legal Connect Android Build Steps

Target: Google Play Console Internal Testing only. Do not use this as a public production release checklist yet.

## Project Summary

- App name: Legal Connect
- Package name: `in.legalconnect.app`
- Version code: `1`
- Version name: `1.0.0`
- Android project folder: `android`
- Live web app: `https://www.legal-connect.in`
- Backend health: `https://www.legal-connect.in/api/health`
- App approach: native Android WebView shell

The Android app loads the live Legal Connect platform inside a clean app shell. Legal Connect pages stay inside the app. External links are opened through the device browser where appropriate.

## 1. Web Build Check

From the repository root:

```powershell
cd "C:\Users\user\Documents\Codex\2026-06-22\you-are-a-senior-full-stack"
npm install
npm run build
```

## 2. Open Android Studio

Open this folder only:

```text
C:\Users\user\Documents\Codex\2026-06-22\you-are-a-senior-full-stack\android
```

Then:

1. Wait for Gradle Sync.
2. If Android Studio asks to install Android SDK/build tools, allow it.
3. Do not open the repository root as the Android project. Open only the `android` folder.

## 3. Run Debug Build on Phone

1. Enable Developer Options and USB Debugging on the phone.
2. Connect phone by USB.
3. In Android Studio, choose the `app` run configuration.
4. Press Run.
5. Confirm the app opens `https://www.legal-connect.in`.

## 4. Generate Signed Android App Bundle

In Android Studio:

1. Go to `Build`.
2. Select `Generate Signed Bundle / APK`.
3. Select `Android App Bundle`.
4. Choose `release`.
5. Create or choose an upload key.
6. Build the signed bundle.

Suggested keystore path:

```text
C:\Users\user\Documents\legal-connect-upload-key.jks
```

Suggested key alias:

```text
legalconnect
```

Keystore warnings:

- Do not commit the `.jks` file.
- Do not share the keystore password.
- Save the password somewhere secure.
- Keep the upload key backed up. Losing it can block future app updates.

Expected `.aab` output:

```text
C:\Users\user\Documents\Codex\2026-06-22\you-are-a-senior-full-stack\android\app\build\outputs\bundle\release\app-release.aab
```

## 6. Razorpay Testing Notes

- Razorpay Checkout is launched by the live web app inside the WebView.
- JavaScript, DOM storage, cookies, third-party cookies, and popup handling are enabled.
- The app does not force UPI.
- The app does not prefill a UPI ID.
- Payment is not marked paid locally.
- Backend verification remains mandatory.
- Work Completion Hold activates only after verified payment.
- For test UPI, backend must use `rzp_test` keys.
- UPI success test: `success@razorpay`
- UPI failure test: `failure@razorpay`
- If Razorpay checkout fails inside WebView during beta, test payment through mobile browser fallback.
- If UPI says invalid, confirm Razorpay test mode keys or use Razorpay test card method.
